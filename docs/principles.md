# 设计原则与判据清单

> 来源：对话阶段的教训整理（2026-10-28 快照）。结论的理由与边界在 `decisions/`，
> 缺口与未接线项在 [`GAPS.md`](../GAPS.md)；本篇只写可复用的判断规则——先问判据，再选方案。

## 一句话

判据答不上来的方案，通常是在用「能力限制」掩盖一个时序或结构问题。

## 一、五条判据

### 1. 这条会不会影响算出来的值？

- 怎么用：会 ⇒ 必须进产物、必须静态（装配期确定）；不会 ⇒ 可动态、可默认、可由宿主注入。
- 反例：把「成本上界」做成作者要手写的声明字段——它只影响耗时，却因为写错而影响结果。

### 2. 它能不能从 (初始态, 输入流) 重建？

- 怎么用：能 ⇒ L2，接受 O(n) seek（重放）；不能 ⇒ L3，拒绝。
- 反例：把弹簧 / 求解器 / 粒子当成「破坏确定性」拒之门外。它们只是 L2 成员，代价是 seek 要重放。
- 详见 [确定性四层](guides/determinism.md)。

### 3. 危险能力要有语法标记，不能藏在看起来普通的通道里

- 怎么用：会读全局或跨对象状态的能力，必须在类型或语法上可见；普通通道只承载「本帧的值」。
- 现成例子：`Dt` 不开成通用通道；live query 不作默认；`Replay` 不暴露给作者。
- 反例：把采样周期做成普通数值通道，作者一句乘法就把作品固定在帧率上，而产物里看不出来。

### 4. 派生量不进产物

- 怎么用：能由已有数据算出来的（时长、类型注解、分析结果、静止时刻）一律现算；产物只存不可推导的输入。
- 反例：ZSB 曾把静止时刻写进 Meta；不可推导时只能填 0 ⇒ 用假值冒充「未知」（GAPS `AH-04` / `AH-05` 已关闭）。
- 另一面：**不可推导的输入必须进产物**。内容曾只存烘焙轮廓、丢掉源字符串 ⇒ 换字体重烘焙做不到；现在源与烘焙同时进产物，restore 用结果、rebuild 用源（GAPS `CD-02` / `CD-03`）。同一形态此前出现过三次（W1-01 对象 id、CC 的 `ClockId`、字体度量）。

### 5. 不知道就说不知道，不给默认值

- 怎么用：报错、或返回「无 + 理由」；不吞返回值、不用 0 冒充未测出、不在多个后端之间自动选一个。
- 反例：延迟 Spawn 的返回值被丢弃 ⇒ 组件未登记时对象安静地少一个（`apply_deferred`）。
- 机制落点：类型声明不符即报错、codata 的「不生产即错」、跨 crate 重名必须登记、路由拒绝必带理由。

## 二、反复出现的错误模式

### ① 用「能力限制」去解决本该由时序或结构不变量解决的问题

| 提过的限制 | 正确替代 | 本质 |
|---|---|---|
| 上界必须进产物 | 值对作者隐藏，只在求值时限上生效 | 用边界而非声明 |
| 要求作者补总时长 | 扫描时间谓词推导 | 用派生而非存储 |
| query 要限制作用域 | 模块装配也是装配期 | 用时序不变量而非能力限制 |
| 每个递归点声明上界 | 默认值 + 动态决策 | 同上 |

⇒ 限制会误伤、会把责任推给作者、会造第二个来源；不变量不会。

### ② 把「有 / 无」当成布尔，而它其实是谱系

确定性 L0–L3、pointwise 污染、seek 代价都是连续量。判定一次「是否确定」没有意义，
要问的是「在哪一层、代价是什么」。

### ③ 数字与文档不同步

数错条数、常量改了而文字没改、只写回复不写文件，都属于同一类：人肉同步。
对策是让数字由机器数（GAPS 小计、门禁），文字与常量改动进同一个提交。

### ④ 忘记「慢路径不能删」

零拷贝 / 快路径是协商成功的奖励，不是唯一路径。删掉慢路径，跨 wasm 立刻死。

### ⑤ JSON 浮点不是「正确舍入」的（1 ULP）

- 现象：`serde_json` 未开 `float_roundtrip` 时，`to_string` → `from_str` 会把同一个 `f64`
  变成 1 ULP；RPC 回执与离线回执的 `outcome` 因此差一位（CI 实测）。
- 判据：任何「逐位相同」都要覆盖**序列化往返**，不能只比内存里的值。
- 对策：`serde_json` 打开 `float_roundtrip`（根 `Cargo.toml`），并让回执用例走真实编解码。

### ⑥ 输入事件的生命周期（同型两次）

- 现象：CH-05 是**装填侧**（GUI `begin_frame` 整帧覆盖 `InputEvents`，RPC 注入失效）；
  `dc8500d` 是**清理侧**（帧末不清空，上一帧的滚轮事件被当成"已投递"继续施加，
  缩放每帧重复一次）。
- 判据：输入只属于一帧——装填（保留已投递 + 追加窗口事件）与清理（`Advance` 之后）
  必须在**同一条帧序**里，且判据要从 `SceneFrame::begin` 走，而不是在用例里手动调
  `clear_input`（见 GAPS `CH-05` / CJ-05 的 B7）。

## 三、结构性教训

### ① 重复造轮子的根因是依赖约束，不是懒

项目里承认过重复（类型名机制在 Pod 层内建、图算法另写一份），原因是依赖方向不允许共享。
⇒ 反制的第一条不是「提醒大家小心」，而是让共享层低到谁都能依赖（纯代数、`no_std` + alloc、
只依赖 serde 的那一层）。

### ② 记账拦不住造轮子——它发生在事后，而造轮子发生在「需要且不知道它已存在」的那一刻

⇒ 需要机器在决策点拦：跨 crate 同名 `pub struct/enum` 必须进白名单，否则结构门禁红。

### ③ 期权 vs 欠账的判据

- 不导致错误结果 ⇒ 期权（可长期持有，从结构里长出来的）；
- 导致错误结果，或由上层需求拉出来 ⇒ 欠账。

⇒ 唯一消费者是 UI 的节点图栈是欠账，不是期权。

### ④ 机制比用途先到是必然的

在内核重建期，「机制建好、入口没开」反复出现。按期权框架它们不是欠账，
但期权堆多了就该兑现——兑现的方式是作品，不是再建一层机制。

### ⑤ 不要照着某个领域的既有理论重构

游戏引擎、控制系统、LLVM 的结论都建立在「连续、数值、不可复现」的假设上；
一旦按「X 该怎么做」决策，就会引入一堆不需要的东西。

⇒ 正确用法：把成熟理论当作检查清单和命名来源，不是设计蓝图。

### ⑥ 同一条约束反复出现，说明它是不变量而不是巧合

「派生量不进产物」看起来是判据 4 的一个应用，实际已经出现过七次：
`W1-01` 的 id、CC 的 `ClockId`、字体度量（`MetricsDb`）、CD 的双轨
（`restore` / `rebuild`）、`Frame`、CH 的 `TraceReport`、CK 的关系编译索引
（`TreeIndex` / `DagIndex`）。每次都在换一层、换一种数据结构，结论却是同一条：
**能算出来的东西不写进文件**。

判据：同一条约束第三次出现时，写进模块文档；第六次出现时，写进这张表。
写进表之后，新批次不再逐次论证，而是直接引用 —— 除非能说清"这次不成立"
（每个反例都要留下不成立的条件，见 `decisions/`）。

### ⑦ 关系语义编译成纯值索引，重算而不是增量（CK）

树 = 归属（入度 ≤ 1），DAG = 依赖（可多入度），几何偏序（遮挡）= per-pixel、
随相机视口变化的另一类语义。三者不要混成一套运行期关系对象：

- 声明（`Parent` / `Layers` / `Expr` 节点）保持各域原样；
- 编译产物是纯 `Vec<u32>`（Euler 区间 / 双向 CSR + 拓扑序），不持句柄、不进 payload；
- `revision = hash(声明，排序后)`；变了就**整体重算**，不做增量维护。

三条反面约束（`ze-graph-algo` 的 `relation` 模块与 GAPS `CK-18` 都写了）：

1. **不做增量索引**：插一个节点 `in/out` 全体偏移，插一条边 topo 可能整体变；
   增量结果必须与全量重编译逐位对拍 ⇒ 增量白写，还引入插入顺序依赖。
2. **不建通用 `Relation` 运行期类型**：编译产物只有 `Vec<u32>` 与声明期 id 列表。
3. **不沿关系传播 tag**：归因靠快照差分（`debug.rs`），传播会改遍全仓、必漏、
   并引入隐式状态。

判据：`all_nodes` 换顺序，产物仍逐位不变；一次点击的归因链里找不到任何被传播的 tag。

### ⑧ 一个控件 = 一份声明 + 一个 `dyn` 实现 + 一段命令列表（CL）

三层各归其位：`WidgetDecl` 纯值进产物；编译索引（`TreeIndex` / revision）回放端重算；
`WidgetRuntime { BTreeMap<Id, Box<dyn Widget2D>> }` 是运行期 Resource、零序列化。
容器不持有子对象 —— 层级由 Euler 切片给出，两遍扫描只在一段 `Vec` 上跑。

三条反面约束（`ze-interact::widget` 模块头与 GAPS `CL-10` 都写了）：

1. **不把 `Box<dyn>` 注册成 ECS 组件**：会撞 `Component` 的 `Clone` blanket impl、
   封闭白名单，以及「组件要进产物而 dyn 不可序列化」的死结。
2. **不做 CSS 式全局样式表**：token 扁平、按 `role` 查表，不做层叠 / specificity /
   继承链；约束与样式都局部、显式、按稳定序。
3. **不给 ctx 开反查其他 Widget 的入口**：签名里没有 `&World` / `&mut`；一查就退回
   树递归，CK 的 Euler 切片白做。

theme 拆 `LayoutTokens` / `PaintTokens`：前者进 revision（字号 / 间距改 measure 结果），
后者只改命令列表。整块 theme 进 revision 会导致「换颜色也重排」，只让 paint 进
revision 会导致「换字号但 bounds 还是旧的」—— 两种都是「错了不报错」。

## 四、一个提交前怎么用这张表

1. 五条判据逐条过：值 / 可重建 / 危险标记 / 派生量 / 未知时是否给默认值；
2. 归类到四条错误模式，看是不是又在用限制解决时序问题；
3. 结构性判断：这是期权还是欠账？共享层够低吗？需不需要在决策点加机器拦截。

## 五、两条元规则（冲突时的裁决依据）

前面那些规则回答「怎么做」；这一节回答「**撞上了怎么裁**」。CI 批次起，
任何规则与「保留旧格式读取分支」冲突时，以本节为准。

### 元规则 A：零消费者只约束实现，不约束形状

- **可以等**：shaping / bidi / 数学布局 / 富文本模型这类**实现**，没有消费者就不做。
- **不能堵**：trait 入口、枚举变体、种类 / 键的**形状**是纯数据、零运行期成本，
  必须一次留对；否则后面每批都变成契约变更。
- 判定：只定义入口、种类或键的形状，不定义语义；默认路径与今天**逐位相同**；
  新增口子不得引入新依赖、不得增加运行期分支、不得改变默认计算结果。

### 元规则 B：正确性、一致性优先于兼容性（项目当前阶段）

- 现在没有外部用户 ⇒ **不为不存在的旧产物保留读取分支**。二义性是永久成本；
  正确性论证不该测两遍。
- 格式**版本号**要留（诊断能说清"这是哪一版写的"）；要删的是「读取旧版本的分支」。
- 领域缺省（"字段本来就可以没有"）保留；兼容缺省（"老格式没这个字段，所以默认成 X"）
  删除，改**必填 + 解码期 fail-fast**——静默兜底比报错危险得多。
- 判据措辞：基线**允许重录**，重录后同一概念只有一种表示、结果可逐位复现；
  不写「保证既有 payload 不变」——那是兼容性承诺，不是一致性判据。

> 两条合起来是同一条：**对未来留形状（纯数据、零运行期成本）；对过去不留分支
> （二义性、永久成本）。**

元规则 B 与[确定性四层](guides/determinism.md)不冲突：四层描述**值怎么重建**
（L0–L3），元规则 B 描述**格式怎么读**（只读当前版本）。删的是"读取旧格式的分支"，
不是任何确定性层级；`Replay` 仍是 AI-07 红线，不走兼容性论证。
