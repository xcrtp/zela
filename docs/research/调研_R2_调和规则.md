# 调研 R2 · 调和规则的两个方向

> 方向定义
> **正向**（mesh 有缺口 → 默认值补齐）：已有，但散落在写出端的手工兜底
> **反向**（shader 要什么 → mesh 没有）：现在完全不存在
> 性质：只读调研，不改任何渲染代码 / shader

补充说明：

- **UV 语义上不是"兜底"而是"生成"**。`fallback_uvs` 依赖包围盒与投影方式，不是常量，进不了"语义 → 默认值"表。抽象时它应留在生产端作为**生产者策略**（`UvProjection`），默认值表里只放标量常量（`(0,0)` / `(0,0,1)`）。
- **2D 侧没有兜底**：`Tessellation2D` 的 `vertices: Vec<Vertex2D>` 是定长结构体，四个槽必然齐备，缺槽无从表达。⇒ 正向调和的天然落点是 3D 生产端，不是通用顶点层。

## 2. 反向：结论是**不支持常量顶点属性**

### 2.1 结论

**wgpu 30（WebGPU 口径）没有"顶点属性缺失时由驱动填常量"的能力**（OpenGL 的 `glVertexAttrib4f` 那套在这里不存在）。shader 声明了 `@location(n)`，管线顶点状态就必须提供 location n，否则**创建管线直接失败**。

替代方案只有一个可用的：**在写出端把缺的槽按默认值表补进顶点字节**（即把正向机制通用化），保持"单布局、单 buffer、不新增 shader"。

### 2.2 证据（本机 wgpu 30.0.1 源码）

| 事实 | 证据 |
|---|---|
| 顶点属性结构体没有"常量值"字段，只有 `format` / `offset` / `shader_location` | `wgpu-types-30.0.1/src/vertex.rs:97-104` |
| 顶点缓冲布局只有 `array_stride` / `step_mode` / `attributes` | `wgpu-30.0.1/src/api/render_pipeline.rs:76-85` |
| 缺失 location 在管线创建期报错 | `wgpu-core-30.0.1/src/validation.rs:1554-1560`：`inputs.varyings.get(&location).ok_or(InputError::Missing)`；错误串见同文件 `:434` —— `Location[{location}] {var} is not provided by the previous stage outputs` |
| 那张 `varyings` 表的唯一来源是顶点状态的 attributes | `wgpu-core-30.0.1/src/device/resource.rs:4355`：`io.varyings.insert(...)`，在此前的属性遍历里填充 |
| "绑一个 1 顶点缓冲当常量"不可行 | `wgpu-core-30.0.1/src/command/draw.rs:36-38`：`Vertex {last_vertex} extends beyond limit {vertex_limit} imposed by the buffer in slot {slot}` —— `Vertex` 步进的缓冲按 stride 限制可寻址顶点数 |

> 注：`validation.rs:1563-1564` 有一句注释 "For vertex attributes, there are defaults filled out by the driver if data is not provided"，但它位于 `inputs.varyings.get(..)` **成功之后**的类型相容分支里，只解释"类型不必逐位相同"，不构成"可以不给这个 location"的依据。

### 2.3 三种替代方案对比

| 方案 | 做法 | 可行性 | 代价 |
|---|---|---|---|
| **A. 写出端补齐**（建议） | 按 `ShaderRequirements` 逐槽查默认值表，缺的槽写进顶点字节 | **可行**；与现状同一机制，只是把手工兜底换成查表 | 顶点字节变宽（例如给缺法线的几何补 12 字节）；无新 buffer、无新 shader |
| B. 专用兜底 buffer | 以 `Instance` 步进绑第二个 buffer，长度 1 个元素 | 只在 `instance_count == 1` 时成立；与实例化路径冲突，且要每槽一条缓冲 | 不可作为通用机制 |
| C. 显式拒绝 | mesh 缺必需语义时直接报错，不渲染 | 可行，但会把"能画"变成"不能画" | 只适合当 A 的兜底策略（补表里查不到的值时） |

**建议：A 为主，C 作为"表里没有该语义默认值"时的显式失败路径**（不静默、不猜值）。

## 3. 对实施阶段的要求

1. 默认值表必须逐位保持 `(0,0)` / `(0,0,1)`，抽象后不允许"顺便优化"。
2. `fallback_uvs`（按包围盒生成）不并入默认值表，留在生产端。
3. 反向调和不能改 shader：需求声明只用于**校验 + 补齐**，不改变 shader 读哪些 location。
