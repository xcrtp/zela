## 3. 两条结构性发现

**① 布局在录制期"现造"，不随 draw 携带。**
`Skeleton` / `PreparedDraw3D`（[wgpu_3d.rs:222-229](file:///d:/Users/xcdh/Desktop/xc/zela/crates/render/zela-render-backends/src/wgpu_3d.rs#L222-L229) 的 `PipelineKey`，以及 `record_prepared` 的入参）都不含 `VertexLayout`；[:1318](file:///d:/Users/xcdh/Desktop/xc/zela/crates/render/zela-render-backends/src/wgpu_3d.rs#L1318) 每次现调 `standard_3d()`。

⇒ 后果：只要出现**第二种 3D 布局**（缩窄的 Lines 布局、带骨骼的布局），后端就无法知道"这条 draw 是哪种"，管线会被错配。**"布局随 draw 携带"是任何多布局方案的前置条件**，不是可选项。

**② `stride` 没有第二份硬编码，但"8 个 f32"有。**
后端全部经 `layout.stride` 取值；唯一重复表达是生产端的 `VERTEX_3D_FLOATS = 8`。抽象布局时该常量应改为由布局推导（`stride / 4`），否则两处会漂移。
