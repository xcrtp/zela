# 确定性四层

> 决策记录：[001-确定性谱系](../decisions/001-确定性谱系.md)。
> 本篇只写口径与判据，不复制决策的理由段。

## 一句话

确定性是谱系，不是开关。问「是否确定」没有意义，要问的是「在哪一层、seek 的代价是多少」。

## 一、四层

| 层 | 状态的形式 | 任意 seek | 判定 |
|---|---|---|---|
| **L0** | `state = f(t)` | O(1) | 最强：任意时刻直接算 |
| **L1** | `state = f(t, 输入流)` | O(1) | **项目所在层** |
| **L2** | `state = fold(seed, 输入流)` | O(n)，需重放 | 可接受：可复现，代价是 seek 要跑前缀 |
| **L3** | 依赖环境（墙钟 / 随机 / 进程状态） | 无保证 | **明确拒绝** |

## 二、判据（唯一一条，可判定）

**能不能从 `(初始态, 输入流)` 重建？**

- 能 ⇒ L2 及以内，可以进来，代价写清楚；
- 不能 ⇒ L3，拒绝。

推论：弹簧、数值积分、粒子、spawn 钩子**不是**「破坏确定性」，它们是 L2 成员。
把它们挡在门外是误判；正确的做法是承认 seek 从 O(1) 变成 O(n)。

## 三、当前项目在哪一层

**L1**：每帧状态由「时间 + 本帧输入」决定，绑定是纯函数，seek 到任意帧不需要跑前面的帧。

同时**接受 L2**：有记忆的演化器（弹簧 / 积分）只要状态可序列化、可清空、可重建，就能进——
`Cache` 作显式参数（`eval(state, input) -> (state', value)`）让「清空重算逐位相同」从纪律变成类型事实。

**拒绝 L3**：见下节第四判据。

## 四、每层允许什么

| 层 | 允许 | 不允许 | seek 口径 |
|---|---|---|---|
| L0 / L1 | 纯函数绑定、可分析的谓词（退化为区间集判定） | 读全局可变状态、读墙钟、读随机数 | **O(1)**：任意帧直接算 |
| L2 | 有记忆演化（状态必须显式、可序列化） | 把状态藏进全局 / 线程局部 | **O(n)**：按 `Replay` 语义重放前缀 |
| L3 | — | 任何依赖宿主环境的行为 | 无保证，直接拒绝 |

**第四判据（不依赖环境）**：确定性 = 输入相同 ⇒ 输出相同，**且无隐式可变状态**。检查项固定五类：
全局可变静态、墙钟、随机、系统环境（字体 / 路径 / 语言环境）、进程计数。
这条判据把三个分头修过的坑统一成同一规则的实例（GAPS `AF-01`）。

seek 口径是推导出来的，不由作者声明：无记忆 ⇒ O(1)；谓词不可分析 + `Hold` ⇒ 保守记 `Replay`。
`Replay` 是给有记忆演化保留的正式口径，不是死代码，不得顺手删除；但它**目前没有生产消费方**
——有记忆的演化器还没接到作者侧（GAPS `AH-07` / `AR-11`）。

## 五、三种「确定性」口径，别混用

| 口径 | 含义 | 现状 |
|---|---|---|
| 同目标可复现 | 同一二进制、同一设备，两次运行逐位相同 | ✅ 最硬，门禁默认口径 |
| 跨端结构一致 | 不同设备上结构指纹相同 | ✅ |
| 跨端逐位相同 | 不同 GPU / 字体 / 编码器上像素逐位相同 | ❌ 已知可接受 |

讨论确定性时必须说明用的是哪一行；把第三行当成定义，会让所有讨论都变成「做不到」。

## 六、结构指纹 vs 像素哈希

| | 结构指纹 | 像素哈希 |
|---|---|---|
| 覆盖什么 | 组件字段（按唯一地址表逐对象读回）+ 世界矩阵 | 渲染结果的字节 |
| 输入性质 | 纯数值，**不含派生几何** | 投影：GPU / 字体 / 编码器都在里面 |
| 能否跨设备 | 可能（第一性承诺 `state = f(t)` 的等式一侧） | 不能，本机基线 |
| 粒度 | 逐帧独立，差异直接定位到帧号 | 帧序列哈希，只能知道「变了」 |
| 用途 | 回归判据的等式 | 端到端兜底 |

两条一起看：结构指纹说「算错了没有」，像素哈希说「画出来一样不一样」。
已知盲区：结构指纹对 `AnimValue::Path` **按变体排除**，一旦路径可动画就对几何失明（GAPS `AR-08`）。

## 七、入口

- 结构指纹：每帧在「推进之后、渲染之前」计算，基线在脚本目录的 `structures.txt`；
- 像素哈希：逐作品逐后端的帧序列哈希，基线见 `FRAME_HASH_BASELINES.md`；
- 门禁：`cargo verify --step hashes`（对表按「作品 × 后端」显式指定，不走路由），
  比对实现见 [`xtask/src/main.rs`](../../xtask/src/main.rs)。
