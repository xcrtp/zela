# 003 · 图灵完备边界

> **状态**：已采纳
> **锚点**：GAPS AF-02 · `ze_comb::expr::Node`
> **被谁取代**：—

## 决策

表达式层**不追求图灵完备**，并把边界写死：

- **结构递归 = 原始递归 = 全函数**：组合子（Functor / Applicative / Monad，无 `fix`）的 bind 次数由项的语法结构决定，因此保证停机，但没有无界搜索。
- **`Fix` + fuel 逃生舱暂不开放**：一开就撕掉全性保证，且当前没有兑现场景。
- **终止性与成本上界分开处理**：终止性由结构守卫在装配期静态检查；成本上界由声明给出（`CodataSpec { depth, max_nodes }`、`Σ` 的上界、求解器的 `dt_min/dt_max`、单态化的 `MAX_INSTANCES`），超出即显式失败。
- **装配期 Lua 循环保留**：那是图灵完备的元编程，只在装配期跑，不进每帧求值。

真正需要「无限结构」时用 **codata**（生产性展开），而不是 `fix`：codata 有观察者与节点预算，展开到哪一层是显式参数。

## 理由

全性保证是这个内核最有价值的性质之一：它让「这段表达式会不会不返回」从运行期风险变成编译期问题。一旦开放 `fix`，所有关于停机的推论都要重新加前提，缓存、seek、产物序列化都会跟着变成「可能不终止」——代价远超收益。

把「终止性」和「成本有界」拆开，是因为它们本来就是两件事：结构守卫能证明会停，但停之前要跑多少步可能取决于运行时值（例如曲面的细分深度）。只证明前者会让最坏情况不可控，所以上界必须显式声明并进产物。

保底手段是装配期脚本：真正的元编程需求（生成大量对象、按数据表批处理）在装配期用 Lua 循环解决，不需要污染每帧求值。

## 反例 / 边界

- **需要无界搜索时必须改写形状**：可以走「有界循环 + 上限进产物」，上限进产物后超出会显式失败，而不是悄悄截断。
- **codata 不是「无限计算」的挡箭牌**：它只表达可观察的无限结构；如果展开逻辑本身需要搜索（例如「找到第一个满足条件的层」），那是另一种能力，不在本决策覆盖范围。
- **未来若真有工作流需要图灵完备**：正确做法是新增一个**独立 pass / 独立求值器**并显式标注其非全性，而不是放宽本决策——边界可以并存，不能被稀释。
- **成本上界写错会误伤**：上界是作者声明，写小了会在合法输入上失败。因此上界要「够宽且显式」，不能靠默认值兜底。

剩余缺口见 GAPS `AF-08` 段。
