## 决策

作者面只兑现「已经有真实用例」的能力，并且用**数据 + 缺省**替代新操作：

| 能力 | 形态 |
|---|---|
| `clock.range(lo, hi)` | 窗口 predicate 的构造器（取代每段动画手写区间判断） |
| `clock.time_of(c)` | 在绑定时钟上取局部时间（多时钟共存的最小出口） |
| `expr.method` / 组件方法（如 `Reveal.current_pos(curve)`） | 方法取代「只读派生通道」的特殊路径 |
| `bind_each` + `query_self` / `exists` | 装配期展开成 N 条具体绑定，产物里没有 query |
| `nat_rec` / `rec_prev` / `rec_index` | 有界递归的唯一作者入口 |
| `wait` / `parallel` | **不加 API** |

`wait` 等价于 `clock.shift`；`parallel` 是「共用同一 clock」的缺省状态，不是一个操作。危险能力必须有语法标记，不能藏在看起来普通的通道里。

## 理由

`wait` 和 `parallel` 不加 API，是这套设计里最能说明立场的一条。旧模型里它们是「操作」，因为脚本有一个全局时间游标；时钟变成数据之后，「顺序」就是给时钟加位移，「并行」就是什么都不做——**并行从一个操作变成缺省状态**。这不是省了 API，而是把状态从脚本里拿走了。

方法（`MethodSpec`）取代只读通道，是因为「派生量」不该出现在可写通道表里。`Reveal.current_pos` 过去以只读通道的形式存在，导致 `channels()` 要额外排除它、写端要专门报 `ReadOnly`；改成方法后，读集（`reads`）可以静态声明并参与帧内定序，写不出假值也成了结构事实。

`bind_each` 在装配期展开，而不是运行期查询，是为了让结果集在装配完成时是**确定的**：按 `ObjectId` 升序展开后，产物里既没有 `it` 也没有 query，回放端无需理解查询语义。`it` 用哨兵句柄表达（不是闭包），守住「禁闭包」这条可序列化约束。

`nat_rec` 的 `count` 在装配期强制非负整数，非整数显式报错、要求作者自己写 `Floor`——这是「不静默」的直接应用：宁可让作者写一步取整，也不替作者猜。

## 反例 / 边界

- **`bind_each` 不是运行期 query**：对象集合变化必须重新装配；想要「每帧重新查询」的需求不在本决策覆盖范围内。
- **`wait` / `parallel` 不加 API 的前提是时钟已是数据**：如果将来需要真正的并行宿主调度（多条时间线同时推进且互相可见），这个前提就不成立，届时应新增显式的时间线概念，而不是把 `parallel` 补回成操作。
- **含 `nat_rec` 的绑定必然是 `Replay`**：作者用了递归就要接受 O(n) 的 seek 代价，没有例外。
- **`Bounds` 目前只有核心侧可达**：`Rect2D` 要走 `Bytes` 才能过脚本边界，因此 `Object.bounds` / `Circle.bounds` 还没有作者出口；这属于值系统收敛的前置，不是 API 设计问题。

剩余缺口见 GAPS `AP-08` 段。
