# 005 · 类型与反射

> **状态**：已采纳
> **锚点**：GAPS AM-01 · AM-02 · AM-04 · `ze_type::ty::TypeSpec` · `ze_reflect::codec::TypeRegistry`
> **被谁取代**：—

## 决策

类型系统拆成两个 crate，职责按「有没有运行时状态」划分：

- **`ze-type`**：纯代数（`no_std + alloc`，零运行时状态）——`TypeSpec`、`Layout`、合一、`ReflectError`、单态化上界。
- **`ze-reflect`**：运行时——interning arena、符号表、句柄表、能力协商、`Codec`、`MonoCache`。

配套四条：

1. **统一解析协议**：慢路径（可序列化、需校验）→ 一次性 resolve → 快路径（进程内、无需校验）。
2. **符号表本身就是一个 handle arena**：句柄是运行时对象的符号，符号是编译期对象的句柄，同一数据结构的两面。
3. **`Layout` 收进 `TypeSpec::Struct` 做字段**，不再平行存在；`None` 是安全缺省。
4. **名义类型**：`Struct` 同名不同布局 = 冲突，因为 `namespace + name` 是跨 Pod 的契约。

**慢路径不能删**：零拷贝是「协商成功」的奖励，不是唯一路径。

## 理由

把「代数」与「运行时」切开，是为了让共享层低到谁都能依赖：`ze-type` 只依赖 serde 且 `no_std`，kernel 各层都能引它，不会因为「引了就要拖进一整套运行时」而被迫重复定义类型。这也是压掉「同一概念两处定义」这类重复造轮子的根本手段——先让共享层足够低，再谈纪律。

统一解析协议解决的是跨边界问题：可序列化的慢形式必须能校验（否则跨进程 / 跨 wasm 时无法判断对端是否同名不同义），而进程内每帧都校验是不可接受的。一次 resolve、之后走快路径，兼顾两头。

`Layout` 收进 `Struct` 是「一个概念只有一处定义」的具体体现：布局不是独立实体，它是结构类型的一个字段。同名不同布局判冲突，是因为名字是契约——两个 Pod 用同一个 `namespace + name` 却给不同布局，任何一方序列化出去都会让另一方读错。

## 反例 / 边界

- **单语言、单进程宿主可以只走快路径**：但不能因此删掉慢路径——删掉之后跨 wasm 的路径立刻不存在。
- **名义类型下同名同布局也算冲突**：实现上两边语义可能一致，但契约上无法保证未来一致，因此仍须登记；白名单是「已声明的债」，不是豁免。
- **generation 只解决失效检测**：它不提供内存安全，也不防止逻辑上的 identity 复用错误。
- **值系统尚未收敛**：`TypeSpec` / `Value` / `AnimValue` 仍是三套变体，投影层存在缺口（例如 `Path` 的通道投影），跨层传递需要显式转换而不是假定同构。

剩余缺口见 GAPS `AR-06` 段。
