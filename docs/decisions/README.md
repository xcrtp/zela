## 如何写一篇决策记录

**文件命名**：`NNN-短标题.md`，编号三位、递增、不复用（被取代的也留着编号）。

**头部三段**（机器可校验，逐字）：

```
> **状态**：已采纳
> **锚点**：GAPS AF-01 · `ze_time::clock::ClockForest`
> **被谁取代**：—
```

- **状态**只取四个值之一：`已采纳` / `已被取代` / `已废弃` / `提议中`。不写日期、不留空。
- **锚点**写「这条决策能被机器验证的落点」：GAPS 编号（必须真实存在）+ crate 名加 `::` 加符号名（必须真实存在）。
  不确定就不写该锚点，换成确定存在的——**假锚点会让门禁失败，也会让读者白跑一趟**。
- **被谁取代**：只有状态是 `已被取代` 时才填取代者（写相对链接）。其余一律写 `—`。
- **废弃不是删除**：一条决策被推翻时，保留原文、把状态改成「已被取代」、写明取代者；
  直接删掉等于抹掉「当初为什么那样选」，下一个人会重犯。

**正文三段**（顺序固定，都要有实质内容）：

1. `## 决策` —— 选了什么。用可判定的陈述句，不写「尽量」「原则上」。
2. `## 理由` —— 为什么。这是 ADR 唯一不可替代的部分：写约束、写被否决的替代方案、写代价。
3. `## 反例 / 边界` —— **什么情况下不成立**。写清失败形态与触发条件；没有边界的决策通常是没想清楚。

**不写什么**：不复制 GAPS 的缺口清单（只写一句「剩余缺口见 GAPS `XX` 段」）；
不写日期与时间戳；不把「计划」当「已发生」——状态以 `GAPS.md` 与代码为准。
