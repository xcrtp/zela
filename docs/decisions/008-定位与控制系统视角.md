# 008 · 定位与控制系统视角

> **状态**：已采纳
> **锚点**：GAPS AF-01 · AR-11 · `ze_scene_core::animation::binding::BindingTable`
> **被谁取代**：—

## 决策

把动画看成**无反馈、单变量的开环控制系统**，并把这条视角用于三件事：

1. **通用化 = 逐个去掉限定词**：「无反馈」「单变量」「开环」这三个词每去掉一个，就得到一类新能力；去掉哪个、什么时候去掉是显式决策，不是自然演进。
2. **借用检查清单与命名，不照理论重构**：`check_read_order` 就是**直接馈通 / 代数环检测**（独立重新发现），采样周期不暴露给被控对象与「`Dt` 不开成通用通道」是同一判断。但**不按控制系统理论重写架构**。
3. **护城河是确定性，不是通用性**：目标生态位是「可复现的归约内核」，不是「又一个通用引擎」。

## 理由

这个视角最大的价值是**给「不做什么」提供理由**。通用引擎路线上的每个功能都可以问一句「它在控制系统里对应什么」：反馈、观测器、执行器饱和——一旦发现某个需求其实是在要求闭环，就能判断它会同时破坏 L1 的 O(1) seek 与产物可序列化，而不是把它当普通 feature 加进来。

「不照理论重构」同样是结论而非懒惰。LLVM 主动放弃了浮点可复现性（fast-math、不同 libm）；Simulink 生成的代码依赖编译器与 FPU。也就是说，「可复现的归约内核」这个生态位是被主流工具**主动放弃**的，空着。照着它们的架构走，会顺手把「连续、数值、不可复现」这三个假设一起搬进来，正好把我们的差异点填平。

按「既有理论该怎么做」决策还会引入大量不需要的抽象：状态空间、传递函数、离散化方法——它们假设连续时间与浮点自由，而我们的基本单位是「一帧一个确定值」。

## 反例 / 边界

- **一旦引入闭环，本决策的保护就失效**：读取自己写的通道且需要上一帧的值，就是反馈系统。`check_read_order` 会拒绝同帧写后读；若真需要反馈，必须新建「有记忆的演化」原语，而不是放宽检查。
- **累积状态是边界实例**：相机输入（`FpsView{yaw,pitch}` 跨帧累加）既不是 `f(t)` 也进不了绑定表，只能靠「把绑定移出表」让位——这正是开环模型表达力的边界，`AR-11` 记录的就是它。
- **控制系统的连续时间结论不适用**：采样定理、稳定性分析都以连续时间为前提；在 L1 里「采样周期」是宿主的导出量，不参与语义。
- **「不照理论重构」不等于「不用理论」**：命名与检查清单可以借，结构不能借。判断标准是「这个抽象是否带来了我们不需要的假设」。

剩余缺口见 GAPS `AR-11` 段。
